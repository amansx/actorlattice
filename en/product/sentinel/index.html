What exists today

Sentinel is the application people use to run work in ActorLattice. It combines a desktop app with an embedded browser experience, automation, and the tools needed to install, update and monitor the product. It is built to support real business operations; the screens and workflow details will continue to evolve with the teams using it.

The integrated direction

The product design connects application delivery with data, authorization and defined actions. People use screens and forms; actors carry out scoped tasks; permissions remain part of the execution path.

One product, two operating boundaries

The proposed Sentinel Client hosts the interface and asks for operating-system consent before using an approved local capability. Sentinel Server handles connectivity, sessions, health and transport to ActorDB. ActorDB remains responsible for business records and next-action decisions. This keeps transport work from becoming a second owner of matter logic.

For a law firm, that boundary matters when a person selects a local document. The application can request a scoped operation on the device while the business process still knows why it was requested, who authorized it and what result can be shared.

Local capability needs two permissions

A business permission does not override the user's device controls. The design requires both the authorization described by Spinoza and the person's operating-system consent for a file or device action. A document analysis step should be scoped to its chosen input and output; approval for one task does not grant broad access to the firm's files.

Evaluate the whole handoff

For a law-firm workflow, ask how a document request becomes visible work, how an exception reaches the right person and how the approved result reaches the next system. Evaluate those handoffs before adding more automation.

Operate the environment as part of the product

Installation, updates, health checks and recovery affect whether a workflow can be trusted with daily work. Sentinel's target operating lifecycle begins with a declared environment, shows a reviewable change, applies it, verifies health and reports drift or failure. The diagram describes that target; it does not guarantee that every deployment topology is currently supported.

Sentinel provides a usable application and operating foundation today. ActorLattice is bringing that experience together with ActorDB and Spinoza for legal work. The screens and handoffs will evolve as early adopters use the product; ask to see the current experience for the workflow you have in mind.

Where Sentinel fits

ActorDB describes the active-data and durable-work direction. Spinoza describes the authorization boundary. Sentinel provides the application and operating foundation that brings those responsibilities together.

Questions teams ask

Is Sentinel only a desktop application?

Sentinel uses the same client code in its native app and in a web experience hosted by Sentinel Server on your cloud provider. When a workflow needs device capabilities, such as at a point-of-sale setup, the native app can use them out of the box, subject to device and business permissions. When it does not, the same client runs in a browser.

Can it read any local file after one task is approved?

No blanket device access is part of the design. A local action needs business authorization and the user's operating-system consent, with a defined resource and capability scope.

Where do the firm's matter records live?

ActorDB is the proposed owner of ActorLattice's active business state. The firm may retain existing systems as authoritative for some data.
